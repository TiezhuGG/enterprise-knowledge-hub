# 企业知识中枢：产品需求与业务流程

> 文档性质：可讨论、可拆任务、可验收的产品计划；不包含程序实现。本文涉及的容量、时间与质量数字均为规划假设或验收候选值，须在 P0 用真实样本确认。全部演示组织、人员、文档与问题使用虚构数据。

## 1. 产品目标与边界

企业知识中枢帮助员工在自己有权访问的资料中找到可信答案，并帮助知识运营人员维护答案背后的资料。首版的成功标准是“能查到、能核对、权限可靠、维护可控”，P2 增强混合检索，P3 再加入关系推理和受控工具执行。

本计划默认私有化或企业内网部署、中文桌面为主要使用方式、100–500 名员工，初始知识规模 1,000–10,000 份文档；先以 10 路同时问答做压测基线。以上均非系统能力承诺。对外模型调用、文件离开企业网络、保留期限和预算必须由企业确认。

系统的业务链条是：资料进入 → 安全校验 → 解析与分块 → 检索索引 → 审核发布 → 用户查询 → 权限过滤 → 检索与重排 → 基于证据回答 → 核验引用 → 反馈整改 → 持续评测。

| 问题 | 产品行为 | 可观察的结果 |
|---|---|---|
| 文件散落，员工不知道查哪里 | 用知识库归类，提供统一检索与问答 | 可从问题进入文档的具体页码或段落 |
| 旧政策与新政策混在一起 | 当前发布版本、有效期、替代关系 | 默认检索当前有效版本，历史资料明确标识 |
| 大模型生成无依据答案 | 必须提供可访问证据，不足时说明缺口 | 核心事实能逐条回到资料，不伪造引用 |
| 不同部门的资料权限不同 | 身份、知识库权限、文档权限共同判定 | 未授权正文、标题、命中数和关系均不出现 |
| 知识持续变化但缺少负责人 | 所有权、处理状态、复核与反馈闭环 | 能找到负责人，能追踪一份资料的全生命周期 |

### 1.1 首版 P1 的完整范围

- 单组织上线；数据记录从一开始携带 `tenant_id`，跨组织隔离用自动验收验证；不开放多租户计费和自助开户。
- 身份入口支持管理员配置的一种组织登录方式；本地演示账号仅用于隔离的演示环境。生产身份方案在 P0 决定。
- 四类角色、知识库授权、文档级限制、成员禁用、审计记录和权限变更立即生效。
- 支持 PDF、DOCX、Markdown、TXT 手动上传；扫描 PDF 可识别为需要 OCR 并明确提示，OCR 不是首版默认能力。
- 可查看解析预览、分块预览、失败原因、重试任务、发布版本、有效期和文档来源。
- 基于 Milvus 的稠密向量检索与证据限定回答；P2 再增加 BM25、融合和模型重排；PostgreSQL 保存业务主数据和授权状态。
- 中文问答、继续提问、历史记录、引用核验、文档搜索、用户反馈和知识运营整改。
- 建立固定评测集，比较检索与问答方案，具备运行监控、费用记录、备份恢复演练和模型配置。
- 前端采用 React、TypeScript、Vite、Ant Design；NestJS 模块化单体提供业务服务，独立 worker 处理解析、索引与评测任务。

### 1.2 P2–P4 增强范围及进入条件

P2 进入条件是 P1 的权限隔离、引用正确性、关键业务路径和基础评测通过。数据质量与权限尚未稳定时，不以增加 Agent 工具弥补问题。

| 能力 | 阶段与提供内容 | 限制与进入条件 |
|---|---|---|
| 知识图谱 | P3：Neo4j 存储经审核的实体、关系及原始证据；支持限定跳数的关系查询 | 每条关系都能追溯到来源；隐藏未授权节点、边、数量和统计 |
| 受控 Agent | P3：LangGraph 工作流模板、工具白名单、步骤上限、超时、审批与运行回放 | 先支持只读检索和草稿生成；写操作需要单独授权和明确审批 |
| 数据连接器 | P2：从一个经批准的只读来源开始，支持增量同步、凭据轮换和失败补偿 | 确认来源 ACL 映射与删除语义；无法映射的资料不自动发布 |
| OCR 与更多格式 | P2 按需：为确有需求的扫描件做 OCR，保留页码与识别质量提示 | 先评测准确率、成本和私有化部署资源 |
| 组织与审批扩展 | P3：可配置组、审批人和复核规则，必要时对接目录 | 不把部门名称当作不可变身份主键 |
| 更深入评测 | P3：图关系问答、工具选择、审批绕过和提示注入测试 | 采用独立样本，避免把调优集当成验收集 |

P2 还包括 BM25 + dense、RRF、模型重排与检索调试；P4 完成生产监控、容量验证、备份恢复和灰度上线。P1 的监控/评测是最小基线，不代表完整企业运维已就绪。

### 1.3 非目标

首版不做开放式多 Agent 平台、任意脚本执行器、任意外部网站抓取、替代企业全部文档管理系统、无来源的通用聊天、自动训练基础模型或全自动修改生产系统。工作流编排也不开放任意代码节点。图谱是增强特定关系问题的能力，并不替代全文与向量检索。

## 2. 角色、资源与授权规则

### 2.1 四类角色

| 操作 | 管理员 | 知识运营 | 使用者 | 审计员 |
|---|---|---|---|---|
| 配置身份、成员、模型与存储 | 可管理 | 无 | 无 | 可查看获授审计字段 |
| 创建知识库 | 可管理或委派 | 仅被委派时 | 无 | 无 |
| 上传、修改、发布、删除资料 | 需同时有目标库运营权 | 仅负责的库 | 无，后续可扩展投稿 | 无 |
| 搜索、问答、读取资料 | 仍需资源读取权 | 仅获授资料 | 仅获授资料 | 仅获授资料 |
| 给知识库或文档授权 | 管理员或获委派的资源所有者 | 仅被委派的资源范围 | 无 | 无 |
| 查看全站运行和费用 | 可查看 | 自己负责范围的任务 | 自己的问答与任务 | 获授的审计范围 |
| 查看他人问答正文 | 不因管理员身份自动获得 | 不自动获得 | 仅本人 | 需专门内容审计授权 |
| 管理评测与反馈 | 可委派 | 负责范围可管理 | 提交反馈并查看本人处理进度 | 获授范围只读 |
| 导出审计日志 | 专门的审计导出权限 | 无 | 无 | 获授范围可导出 |

角色决定“可以做哪类操作”，资源权限决定“可以对哪些资料操作”。管理员不是默认的全站内容阅读者。P1 不提供隐式超级账号绕过；如企业确需紧急访问，应作为独立需求，配置期限、理由、审批和审计。

### 2.2 统一授权规则

1. 请求必须有有效身份、有效组织成员关系和正确 `tenant_id`；租户由可信会话解析，不能信任客户端自报值。
2. 知识库拥有读者、运营者和所有者授权；文档默认继承知识库读权限，也可进一步收紧。文档不能放宽知识库边界。
3. 可读条件为：具备知识库读取权，并满足文档限制，并且文档处于允许访问的生命周期状态。禁用成员与显式禁止优先。
4. P1 的组权限先以后台管理的稳定组 ID 表达，嵌套组和复杂规则推迟。文档发布者不可绕过这些条件。
5. 过滤发生在检索之前或检索引擎查询内部；候选结果取回后再查权，生成前再校验。索引中的 ACL 只是加速数据，不是最终授权来源。
6. 引用、搜索建议、知识库计数、历史回答、图谱、下载、分享入口与评测样本都复用授权服务，避免旁路泄漏。
7. 撤权后立即阻止新的读取和新的流式片段；已发送给浏览器的内容无法撤回。关闭下载地址、清理缓存并终止受影响运行，记录可验证的完成时间。
8. 无权资源的直接链接使用统一“内容不可用或无权访问”，不区分不存在与无权限；不泄漏原标题、拥有者或全局命中数。

## 3. 关键用户故事与验收条件

| ID | 用户故事 | 首次实现阶段 | 验收条件 |
|---|---|---|---|
| US-01 | 员工询问“差旅报销需要什么材料” | P1 | 仅使用有权且有效的发布资料；核心要求带引用；能打开对应页或段 |
| US-02 | 员工找不到足够信息 | P1 | 不补写政策；展示已找到的范围、缺口与可选澄清问题 |
| US-03 | 员工遇到两份相互矛盾的制度 | P1 | 展示双方有效来源和日期；有明确替代关系则说明依据，否则标记冲突并转交维护 |
| US-04 | 运营人员上传一批文件 | P1 | 逐文件显示进度和失败原因；一份失败不阻塞全部；刷新后可恢复查看任务 |
| US-05 | 运营人员替换现行文档 | P1 | 新版未发布前旧版继续服务；切换后所有默认检索只返回新发布版本 |
| US-06 | 管理员移除员工对某资料的权限 | P1 | 新搜索、历史引用、下载和正在运行的问答均受新权限约束；审计能追踪撤权时间 |
| US-07 | 运营人员发布有生效日期的制度 | P1 | 生效前不进入默认问答；到期后停止默认引用；任务延迟也不能越过请求时校验 |
| US-08 | 员工给不正确的答案反馈 | P1 | 反馈绑定问题、回答、引用版本与运行 ID；运营可以重现并记录处理结论 |
| US-09 | 审计员调查一次敏感访问 | P1 | 可按时间、操作者、资源和动作检索；普通审计日志不默认展开问答或文档全文 |
| US-10 | 运营人员评估新的检索配置 | P2 | 在相同问题集、模型和版本快照下对比；展示样本数量、质量、延迟和费用 |
| US-11 | 员工询问产品与项目的关联关系 | P3 | 返回受权可见的实体路径；每条事实关系有来源；无依据的连接不显示为事实 |
| US-12 | 员工让 Agent 汇总资料并生成草稿 | P3 | 工作流有可见步骤和限制；完成后展示结果与工具摘要；不展示隐藏思考过程 |
| US-13 | Agent 需要执行已开放的写操作 | P3 | 审批人看到具体目标与参数差异；批准只绑定该版本操作；拒绝后不执行 |
| US-14 | 数据源中的资料被删除或撤权 | P2 | 依据连接器语义撤销平台读取并同步索引；无法确认时进入隔离待复核 |

## 4. 核心业务流程与状态机

### 4.1 创建知识库

输入包括名称、简介、负责人、默认可见组、语言、解析策略、发布策略、默认有效期与来源要求。名称用于人类识别，稳定 ID 用于引用。创建后默认仅创建者与显式指定人员可见；不设置“全员公开”为危险的默认值。

创建流程：草稿配置 → 校验负责人和授权范围 → 创建空知识库 → 上传测试文档 → 试查与核验 → 启用。知识库需要最少一位仍有效的负责人；转交所有权成功后才能移除最后一位所有者。

### 4.2 导入、解析与索引

导入批次状态：`待上传 → 上传中 → 已接收 → 处理中 → 全部成功 / 部分成功 / 全部失败 / 已取消`。

单文件处理状态：`已接收 → 校验中 → 待解析 → 解析中 → 待索引 → 索引中 → 待审核`。非法格式、超出限制、病毒命中或来源不可信进入“已阻止”；可恢复的失败进入“失败待重试”。文件原始内容与处理记录分别存储，任务 ID 固定。

- 规划文件上限为 50 MB、单批 100 份，可在 P0 按实际样本调整；上传前显示限制，服务端独立校验。
- 使用内容摘要和幂等键识别重复提交。同内容同目标文档返回已有任务；同内容不同知识库仍分别授权，不能通过重复提示暴露别人的资料。
- 解析保留标题层级、段落、表格、页码或定位锚点；表格跨页、扫描件、无文本和密码文件显示明确结果。
- 页数未知时展示阶段和已完成数量，不伪造百分比；任务成功要以服务端状态为准。
- 任务可取消但不声称瞬间停止全部工作；停止接受新步骤并清理临时数据，最终显示“已取消”或已完成的事实结果。
- 重试从可安全恢复的失败步骤开始；更换解析策略产生新的处理版本，不覆盖已有发布内容。
- 索引准备就绪不等于已发布；未发布内容仅对有审核权限的人可见，不参与普通问答。

### 4.3 审核、发布与版本切换

文档生命周期：`草稿 → 待审核 → 已发布 → 已撤回 / 已过期 → 已归档 → 待清理 → 已清理`。待审核可退回草稿；已撤回或已过期经重新审核可发布新版本。发布版本保持不可变，修订创建新候选版本。

每份文档包括逻辑文档 ID、候选版本、当前发布版本指针、来源、所有者、生效时间、失效时间、内容摘要、处理配置版本和审核记录。知识库的发布策略首版默认为人工审核；是否允许同一人上传并审核由试点治理要求决定，需显式配置。

发布检查：内容预览可读、必要来源字段齐全、有效期合法、权限确认、索引就绪、审核通过。发布操作原子切换当前版本指针，随后异步清理旧索引；检索仍以主数据当前版本判断，不能等索引清理才生效。

旧版本可由获授权的运营人员查看，普通用户默认只见现行版本。历史问答保留当时版本标识；版本不再有效时显示“生成时使用旧版本”，并提供“按现行资料重新提问”。历史原文是否可读仍取决于当前权限和保留策略。

### 4.4 删除、撤权与保留

删除申请 → 确认影响范围 → 主数据标记不可检索 → 关闭下载与引用读取 → 异步删除索引及缓存 → 按保留策略清理原文件和派生数据 → 记录完成证据。

删除确认显示用户有权知道的引用与任务影响；不会展示他人的会话内容。清理失败要有重试队列和告警，不允许因失败重新变成可见。逻辑不可见应在请求时立即保障，物理清理时间单独计量。

保留期限、回收窗口与备份淘汰周期在 P0 确定，计划建议初值分别为按文档类型配置、7 天和 30 天，均需组织批准。恢复只在保留窗口且权限允许时开放；备份恢复必须重放删除与撤权记录，避免把已删除内容重新开放。

### 4.5 一次安全问答

1. 校验登录、组织、会话所有权、所选知识库与预算；没有可读资料时解释如何获得资源访问。
2. 判断问题是否需要澄清、普通检索或限定工具；P1 只提供固定检索与生成工作流。
3. 可做查询改写，但保留用户原问题与改写摘要；把用户可见范围写入检索条件。
4. 稠密向量与 BM25 并行检索，融合、去重、重排；再次确认文档、版本、有效期与权限。
5. 检查证据是否充足、是否有冲突；回答只引用选入上下文的真实证据 ID。
6. 对关键结论提供引用；引用能定位版本、页码或段落，不用模型自由编造的链接。
7. 输出前再做权限与引用校验；每个后续流式片段服从最新权限。发生失权立即中止并显示中性提示。
8. 保存会话、检索配置、模型标识、引用版本、延迟与费用；敏感正文不无条件写入通用日志。

回答结构采用“直接结论 → 必要条件或步骤 → 来源 → 不确定或冲突说明”。支持清晰的“依据不足，无法确认”；允许给出已被证据支持的部分答案，并指出其边界。

多轮对话使用当前会话上下文，不将旧会话中的敏感信息自动带入。用户切换知识库时提示上下文范围变化；后续问题重新检索并查权，不直接沿用旧授权。

### 4.6 无答案、冲突与有效期

| 情况 | 用户看到什么 | 运营后续动作 |
|---|---|---|
| 完全无可用证据 | “当前可访问资料中未找到足够依据”，建议细化问题或切换已授权范围 | 允许提交缺失知识反馈 |
| 有相关资料但无法推出结论 | 给出相关事实和引用，说明不能确认的部分 | 归为答案覆盖不足 |
| 两份同效力资料冲突 | 并列显示不同说法、来源与日期；不擅自挑选结论 | 创建冲突待办，指定负责人 |
| 新版明确替代旧版 | 使用当前有效版本，说明替代关系 | 运营维护替代元数据 |
| 来源已经过期 | 默认不纳入答案；有权查看历史时明确标注 | 通知所有者复核或更新 |
| 用户未获某资料权限 | 仅陈述当前可访问资料不足 | 不说“有三份机密文档不能看” |
| 用户索要与资料无关的高风险外部操作 | 说明当前能力与允许范围 | 不自动扩展工具权限 |

### 4.7 连接器同步（P2）

配置凭据 → 测试连通性与最小权限 → 选择允许同步范围 → 映射来源 ACL → 预览样本 → 人工确认 → 首次同步 → 增量同步。连接器默认只读，抓取目标必须在允许列表内。

同步任务状态：`待运行 → 发现变更 → 拉取中 → 处理与授权映射 → 完成 / 部分失败 / 失败 / 已暂停`。增量游标只在该批处理结果可恢复时推进；来源删除与撤权也属于变更，不仅关注新增文件。

来源超时不等于来源删除；无删除证据时显示同步滞后和资料更新时间。来源授权无法确认时按保守策略停止相关资料读取并告警，具体宽限规则需 P0 明确，不允许静默扩大访问。

### 4.8 Agent 运行与审批（P2）

运行状态：`待开始 → 运行中 → 等待审批 → 继续运行 → 成功 / 失败 / 已取消 / 已超时`；步骤状态单独记录。运行总时长、最大步骤数、最大工具调用次数和费用上限均可配置，默认候选为 120 秒、8 步、5 次工具调用，实际值由 P2 测试决定。

UI 展示“选择检索范围、检索到可用资料、生成草稿”等可核验步骤摘要、工具名称、允许公开的参数、执行结果和引用。不得展示或保存为界面功能的隐藏思维链。

审批记录绑定运行 ID、工具、资源目标、输入摘要与参数哈希、审批人、有效期。参数或目标变化必须重新审批；通过后执行前重新校验权限。批准不是无限期授权，拒绝后不换工具绕过。首轮只读工具不需要弹出无意义的每次审批。

## 5. 数据与业务对象

| 对象 | 用户关心的关键字段 | 业务约束 |
|---|---|---|
| 工作空间 | 名称、负责人、状态 | P1 单组织；空间不等同于无隔离的目录标签 |
| 知识库 | 名称、描述、所有者、读者范围、发布策略 | 至少一位有效所有者 |
| 文档 | 标题、来源、标签、权限、有效期、当前版本 | 内容变化产生版本；标题本身也受保护 |
| 文档版本 | 版本号、摘要、生效时间、处理与审核记录 | 发布后不可原地修改 |
| 文本分块 | 文档版本、位置、标题路径、内容、检索字段 | 引用必须映射回原文，不作为独立授权来源 |
| 会话与消息 | 发起者、范围、问题、回答、来源、生成时刻 | 默认仅本人可见；历史读取重新查权 |
| 任务与运行 | 状态、阶段、进度、错误码、重试关系 | 业务幂等；刷新不会重复执行 |
| 评测集与评测运行 | 问题、期望证据、允许答案、版本快照、结果 | 评测账号也受到资源权限约束 |
| 反馈与整改 | 问题类别、来源运行、负责人、处理状态 | 不向无权运营人员复制敏感原文 |
| 图谱实体与关系 | 类型、规范名、别名、证据、审核状态 | 抽取建议不等于经证实的业务事实 |

## 6. 质量、体验与试点验收

以下是待校准目标，不是现有测量结果。P0 先冻结数据集、硬件、模型、并发和统计口径，P1/P2 再报告实测。

| 指标 | 候选门槛 | 测量方式 |
|---|---|---|
| 权限泄漏 | 固定越权测试集零泄漏 | 覆盖搜索、引用、历史、下载、缓存、流式、图谱和撤权竞态 |
| 引用可核验率 | ≥ 95% | 人工抽样检查引用能打开且支撑对应结论；无权失效按预期状态计 |
| 有答案问题的检索 Recall@10 | ≥ 85% | 带人工相关性标注的独立测试集；按知识类型分别报告 |
| 证据不足时适当拒答率 | ≥ 90% | 明确不可回答样本；同时报告误拒答，避免靠全部拒答过关 |
| 首个有效问答反馈 | P95 ≤ 2 秒 | 指接收状态或进度，不等同于首字和完整答案 |
| 首个回答内容 / 完整回答 | 候选 P95 ≤ 6 秒 / ≤ 20 秒 | 在约定模型、文档规模与 10 并发条件下分别测量 |
| 普通列表和搜索操作 | 列表 P95 ≤ 1 秒；搜索 P95 ≤ 3 秒 | 网络和后端时间分别记录 |
| 导入可解释性 | 100% 终态可见原因 | 人工查看失败、取消、部分成功、重试及重复提交场景 |
| 新用户完成首个有引用问答 | ≥ 80% 在 5 分钟内独立完成 | 5–8 位目标用户可用性测试；记录卡点而非只做满意度 |
| 试点可用性 | 工作时段候选 99.5% | 定义工作时段、观察窗口和维护豁免后统计 |

费用不设置未经验证的单价承诺。记录每次问答的模型用量、重排与图谱调用、处理文件成本和缓存命中；按预算告警。企业可配置模型本地部署或批准的外部服务，UI 明示当前数据路径和配置状态。

## 7. 产品验收任务与学习重点

| 任务 | 产出 | 完成标准 | 学习的 Agent/RAG 概念 |
|---|---|---|---|
| PRD-01 访谈与样本采集 | 角色地图、20 个高频问题、代表性资料 | 至少覆盖制度、操作说明、表格、冲突与无答案场景 | 知识边界先于模型能力 |
| PRD-02 需求与风险定级 | P1/P2 范围、业务优先级、不可接受失败 | 利益相关方确认范围和责任人 | 确定性流程与自主决策的边界 |
| PRD-03 权限建模演练 | 两部门三角色权限样例、撤权场景 | 无授权用户不能推断受限资料存在 | 工具权限与上下文最小化 |
| PRD-04 文档生命周期走查 | 导入、发布、更新、过期、删除故事板 | 每种失败有归属、状态和补救动作 | 工具幂等、状态机和恢复 |
| PRD-05 问答规则设计 | 回答模板、冲突与拒答标准 | 样例覆盖可答、部分可答、不可答 | Grounding、检索与生成解耦 |
| PRD-06 首轮可用性测试 | 任务脚本、观察记录、问题清单 | 关键任务可完成且有后续整改负责人 | 可观察性不等于展示思维链 |
| PRD-07 评测基线 | 冻结的问题集与人工判定指南 | 不同评审能一致判断主要错误 | 评测驱动迭代，防止主观印象 |
| PRD-08 Agent 准入评审 | 工具白名单、预算、审批表 | 每个工具说明可读写什么、失败怎样收敛 | 有界执行、人机协同与最小权限 |

## 8. P0 必须确认的事项

负责人在实施前确认：真实员工数与并发；原始文件类型与扫描件比例；身份提供方；文档所有权及发布审批；内网与外部模型边界；保留与删除要求；第一条连接器；试点部门；可用硬件；预算；是否允许文档下载；全文审计授权；质量与延迟的最终门槛。

这些问题不阻塞先完成计划，但会影响首版交付范围和部署方式。未确认内容保留“待决策”，不能被默认为已获业务批准。
