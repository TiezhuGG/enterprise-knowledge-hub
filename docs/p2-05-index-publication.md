# P2-05 索引发布与安全重建

日期：2026-11-08（Asia/Shanghai）。本项增加显式文档发布、资料库影子重建计划、完整读回、问题对照、原子切换及同内容版本的索引回滚。真实模型质量、企业扫描器与业务人工验收仍待完成；当前不自动下载或部署模型。

## 配置和迁移

```sh
npm run build
npm run db:migrate
npm run test:releases
```

迁移 012 新增 index_release、index_release_item、publication_request、追加 publication_event，以及资料库 active_index_profile_hash。已有发布指针不改变；旧模型配置在切换和回滚窗口内必须保留。发布事件、幂等结果与指针更新在同一 PG 事务提交，If-Match 防止并发覆盖。

原有 EMBEDDING_* 是 `default` 配置。额外配置只允许服务器环境前缀别名，API 不接受地址、模型参数、密钥或原始 profile JSON：

```dotenv
EMBEDDING_PROFILES_JSON={"next":"NEXT"}
NEXT_BASE_URL=http://127.0.0.1:8084/v1
NEXT_MODEL=实际模型名
NEXT_REVISION=固定权重或部署版本
NEXT_DIMENSION=实际维度
NEXT_PROCESSING=cls-token-windows-mean-l2-v1
NEXT_QUERY_PREFIX=模型所需的查询前缀
NEXT_DOCUMENT_PREFIX=
```

凭据使用环境设置中的 `NEXT_API_KEY`，不提交仓库。还支持该前缀下的 BATCH_SIZE/TIMEOUT_MS/COST_PER_MILLION；默认只允许 loopback，远端来源需单独的 `NEXT_ALLOW_REMOTE=true` 配置。各空间沿用服务器统一的 MILVUS_ADDRESS/认证，不能通过 API 改变存储路由。模型空间 hash 绑定模型、权重版本、维度、预处理、查询/文档前缀、归一化、向量 schema 和规范化地址；密钥、批大小等运行参数不影响 hash。API 只返回别名、模型、版本、维度和 hash。

API 与 Worker 都必须保留新旧别名并重启。Worker 按任务已冻结的 hash 选择编码器；普通新版本优先按资料库当前 active_index_profile_hash 构建，否则使用 default。查询按实际已发布代际选择编码器，因此改变 default 本身不会将已发布旧空间误送给新模型。删除旧配置会明确阻止相应空间的检索或回滚，不能静默改用新编码器。

当前 dense 检索要求一次查询范围属于同一模型空间，跨不同空间会返回 SEARCH_MODEL_SPACE_MIXED；请选择一致的资料库范围，不能直接比较不同模型的余弦分数。词法通道仍使用当前授权语料的 BM25，未增加 Milvus Lite 不支持的全文索引。

## 第一次发布文档

文档索引详情增加“核验并发布此代际”。需要当前文档 read/publish 权限，提交 If-Match、Idempotency-Key、明确质量核对和至少 10 字说明；服务端只保存说明摘要。发布只允许 latest_version_id 对应的版本，不提供旧正文回滚接口。

服务端核对：

1. 活跃租户/成员、当前角色、资料库/文档授权、来源授权证明与永久墓碑。
2. 安全检查必须 clean；ready 代际须属于该文档及版本，冻结清单、内容和版本关联完整。
3. required_artifacts 必须是当前受支持的 dense 清单；收据数量、片段身份与检索摘要必须完全匹配，不能缺项或用别的版本补数。
4. 读取固定对象版本，验证 chunk artifact hash；按绑定存储读回全部向量，与当前空间的不可变缓存逐项比较，不只相信 PG 的 ready 标记。
5. 存储 I/O 后重新核对权限和清单。最后事务锁定扫描、代际、存储绑定和收据，比较指针 ETag，再更新 `(published_version_id,published_generation_id)`、事件与审计。

已绑定当前空间的资料库不允许发布其他空间的代际。已导入来源还要求来源 canonical version 一致，撤权、隔离或过期不能通过发布操作重新开放。连接器维护者的 publish 能力仍与资料库授权相交，缺少源端阅读授权时无法核验正文或发布。

安全扫描器没有新增绕过入口：开发集成/浏览器只在隔离夹具中直接模拟扫描通过。真实待扫描资料继续阻塞。若对应任务确实在等待发布且 dense checkpoint 指向此代际，成功发布会将任务记为 succeeded/published；不会错误结束另一个正在运行的构建。

## 影子重建与对照

入口在资料库“文档与上传 → 索引发布与安全重建”。需要当前资料库 manage/read/write/publish，以及范围内每份文档的 read/write/publish，不能静默跳过无权文档。

创建计划固定目标别名/hash，记录**全部当前 active 且正式发布的文档二元组**。首版限制 200 份，超限明确拒绝；没有发布文档时请先进行第一次发布。同一个库仅有一个 building/verified 计划。草稿不属于服务中的基线，也不会因计划自动发布。

“追赶并构建影子索引”重新枚举当前发布集合：纳入新增发布，更新变更版本，移除已删除/归档/取消发布的项目，并清除旧核验结果。每个项目使用稳定构建 key，复用现有持久任务、租约、缓存和失败重试。已有计划重复追赶不会复制原文或重复创建同一构建；中途 HTTP/Worker 中断后可从记录继续。任务失败时通过处理任务界面重试对应任务；调用结果不明仍沿用既有人工核对规则，不能用重建绕开计费保护。

影子代际不会更改文档发布指针。旧代际保持 ready 并继续服务；向量维度改变会使用独立 collection。分块 artifact、解析策略、chunker、embedding profile、配置 hash、文档版本和代际各自保留身份。只换嵌入会复用已核验的解析/分块，重算向量；变更分块/解析策略须先提供兼容的版本化处理器、相应 schema 迁移及新 manifest，再走同样核验与切换，不能覆盖旧产物。本项不新增分块算法，也不声称可以读取任意未来格式。

“完整核验并运行对照”接受 1–20 个脱敏问题与 expected_document_id。参考文档必须属于完整计划范围，不能只选容易通过的子集。先读回基线与候选的全部产物，再用各自编码器在同一个授权范围内实际检索，记录逐题文档 rank、Recall@5、MRR 和阶段耗时。当前评测是文档级 dense 对照，记录当前词法版本/词典 hash；不冒充答案质量、BM25 持久索引迁移或真实 token 费用评估。

问题明文不写入计划，只存 query_hash、预期文档 ID、排名与耗时。请在自己的受控评测库保存原始样本以重现实验。候选 Recall@5 和 MRR 均不低于基线才进入 verified；故意制造排名退化会留下结果并保持 building。样本分数不代替业务真人复核。核验绑定覆盖摘要、基线/候选代际及清单/收据/权限版本；10 分钟后须重新核验。

## 原子切换和增量追赶

人工核对通过后，“准备切换索引 → 确认索引操作”才提交切换。先再次读回候选向量，再在持有资料库事务锁时复核全部当前发布集合、权限和核验摘要。新增文档、发布替换、行/权限变化、扫描拒绝、收据缺失或过期来源使操作失败，必须追赶/重新核验。不是检查单一最大时间戳后就认为增量已追平。

一次事务切换全部项目的 generation 指针、资料库当前空间、对应任务终态与逐文档事件；任意审计/事件写入失败整体回滚。If-Match 与幂等 key 保证重复提交不会重复切换。构建、失败或取消计划均不清空旧发布指针。

## 安全回滚

回滚再次核对旧代际配置、实际向量与全部当前权限。仅在文档仍 active 且当前正式发布版本/候选代际与计划记录吻合时，切回该**同一正文版本**的基线 generation。墓碑文档被排除且永不恢复。已有新正文、新发布文档或不同代际时返回 ROLLBACK_SCOPE_CHANGED，应为当前内容建立向原模型空间重建的新计划，不能强制覆盖。

回滚不会复制历史 ACL、源端 readers、成员关系、扫描状态或文档状态。已撤权用户仍不可读；来源证明失效或发布者失权会阻止操作。新旧引用每次回查仍核对当前正式二元组和当前授权；索引回滚不把旧引用当作访问令牌。

回滚同时更新资料库当前空间，后续新内容继续按该空间构建。取消计划只禁止后续切换，已有影子构建可完成并保留为派生产物，不撤销其他操作共享的处理任务。P1-14 文档删除清理仍枚举全部代际，发布历史仅保留定位与摘要，不用历史 FK 阻止已删除文档物理清理。
