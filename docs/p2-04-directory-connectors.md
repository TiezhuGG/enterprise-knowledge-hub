# P2-04 本地受控目录增量连接器

实现日期：2026-11-08（Asia/Shanghai）。首个来源按用户选择采用本地受控文档目录。代码支持签名导出清单，API 和 Worker 不接受任意文件系统路径。未接入真实企业资料目录；默认关闭同步。此项不部署生成模型、不替代安全扫描或正式发布。

## 配置与启动

先构建并应用迁移 011，然后由维护者在 API 与 Worker 的服务器环境中设置相同绑定：

```sh
npm run build
npm run db:migrate
```

```dotenv
CONNECTORS_ENABLED=true
CONNECTOR_POLL_MS=1000
CONNECTOR_SYNC_INTERVAL_SECONDS=60
DIRECTORY_SOURCES_JSON='{"policies":{"tenant_id":"实际租户 UUID","kb_id":"实际知识库 UUID","source_id":"policies-v1","root":"/srv/knowledge-export/policies","key_env":"POLICY_EXPORT_SIGNING_KEY","freshness_seconds":900,"principals":{"source:staff":{"type":"group","id":"实际本地群组 UUID"}}}}'
```

`POLICY_EXPORT_SIGNING_KEY` 用环境设置保存至少 32 字符的随机签名密钥，禁止写入仓库或聊天。源端导出程序使用该密钥签名，消费端只读目录并验证签名。目录应由受信导出进程写入；消费进程使用只读挂载和独立 OS 身份。签名密钥是来源认证凭据，绝不代表阅读全部文档的资格。密钥值可轮换；双方应协调切换，失败期间读取关闭。绑定根路径、source_id、租户、资料库、密钥变量名或时效窗口变化时拒绝继续，避免旧游标套到另一个来源。

在资料库的“文档与上传 → 本地目录连接器”中输入 `policies` 创建连接器并发起增量同步。别名只能绑定一个租户和资料库；需要当前 `manage/write/delete/manage_acl` 权限，工作线程每次事务重新查询创建者身份与授权。管理身份失效后任务阻塞，不使用缓存角色继续执行。后台默认每 60 秒轮询有效连接器；blocked/paused/removed 不自动重新开放，修复后由维护者发起同步。配置只在进程启动读取，修改环境后重启 API 和 Worker。

权限映射支持本地成员和群组。未映射、已禁用成员或不存在群组使整份文档进入隔离；空 readers 表示撤权。映射变化即使没有内容事件也会重新核验。动态群组成员关系每次读取重新检查，不能靠旧清单恢复已离组成员的权限。

## 导出协议

目录并非“所有文件都公开”的扫描器。导出程序必须生成可证明授权、完整顺序和时效的 `directory-feed-v1` 清单：

- `HEAD.json` 包含 `{payload,signature}`。signature 为 `HMAC-SHA256(JSON.stringify(payload), key)` 的小写十六进制；字段顺序使用实际 payload 的 JSON 序列化顺序。
- payload：`schema/source_id/issued_at/valid_until/end_seq/pages`，可选签名 `not_before` 用于导出端背压。`valid_until-issued_at` 不超过绑定的 freshness_seconds（30–900 秒）；过期或签名错误关闭读取，重读旧清单不会续期。
- pages 是从 seq=1 开始、连续至 end_seq 的不可变事件页引用：`start_seq/end_seq/sha256/file`。每页 1–100 条，首版最多 50 页、5000 事件，总页字节不超过 12 MiB；达到限制须规划后续源协议/存储升级，不能截断旧历史或复用游标。每次追加新页，已封存页禁止扩展或覆盖。
- 事件：`seq/external_id/revision/kind`。`external_id` 为稳定的不透明标识，支持字母、数字及 `._:-`，不使用正文。`kind=upsert` 另需 `readers/file/filename/mime/size/sha256`；`kind=acl` 需 readers；`kind=delete` 明确删除。revision 存摘要，正文不存入事件表。
- upsert 内容限定现有 TXT、Markdown、PDF、DOCX 上传规则和 50 MiB。路径必须相对绑定根目录，拒绝绝对路径、`..`、符号链接、硬链接、非普通文件、越界描述符和哈希不符。页面和内容均有读取上限。
- 导出者先写不可变内容和事件页，最后原子替换 HEAD。只有明确 delete 事件表示删除，缺文件、缺页、目录不可用均不能推断删除。上游已删除内容要在保留期结束后由上游自行清理，本地清理不会修改只读来源。

提供离线辅助程序，**只供受信导出者运行**。其输入是本次新增事件 JSON 数组（最多 100 项），读取 file 指向的根目录内文件，自动补 `seq/size/sha256/filename/mime`，封存新页并替换签名 HEAD。先写原文件，再运行：

```json
[{"kind":"upsert","external_id":"travel-policy","revision":"v1","readers":["source:staff"],"file":"travel-policy.md"}]
```

```sh
node --env-file=.env scripts/directory-feed.mjs policies /secure/new-events.json
# 没有新事件时，仅在确认上游权限仍然有效后续签：
node --env-file=.env scripts/directory-feed.mjs policies
```

每个目录必须只有一个串行导出者。辅助程序不监听目录、不推断 readers、不自动续签；维护者需安排受信导出进程定期核对真实源权限后续签。盲目周期续签旧 ACL 会破坏新鲜度保证。消费者只接受导出者的授权声明，不能独立发现上游尚未导出的撤权。

## 检查点、并发与恢复

PG 持久保存 connector、run、source_item、page 摘要、event 摘要及追加事件记录。连接器使用会话 advisory lock 串行执行；每次领取生成随机 worker_token，每次事务校验 token、当前权限、暂停/移除状态。旧处理者迟到不能提交新版本或检查点。暂停/移除取消活跃 run，立即关闭来源读取；在途对象写可能完成，仍受 P1-14 写入跟踪和孤儿对象清理约束，不能提交来源文档。

先核验完整签名 HEAD 与所有页，再暂存最多 100 事件的权限变更，每轮处理至多 20 项。每项“文档版本、派生任务、来源关联、ACL、事件确认、检查点”在同一事务提交。文件传输在事务外准备，通过持久上传票据恢复；事务失败重用票据，过期后换代。相同 external_id 映射到同一文档，相同内容哈希重用既有版本；新 revision 或重跑不会重复入库。显式源删除沿用 P1-14 墓碑及清理事务；本地人工删除同样不会被后续同步复活，相同外部标识永久跳过。

full 模式表示**完整事件历史校验并追赶已提交检查点**，不重置游标、不复制文档、不按缺失推断删除。消费过程对历史退回、已封存页改写、事件摘要变化一律拒绝。

短暂目录/存储错误最多尝试 3 次，指数退避；签名 not_before 按声明延后且有上限。目录协议没有 HTTP 429，此处验证的是签名背压等待。配置、凭据、过期证明、历史或操作者权限错误阻塞，修复后手动重试。失败不会前进检查点。暂停/恢复/移除使用 If-Match；创建与启动同步使用 Idempotency-Key。一个连接器同时只能有一个活跃同步。

## 阅读门禁与传播时间

读取需要本地角色、知识库和文档 ACL，以及独立的来源门禁同时通过。source_reader 按当前成员/群组计算；连接器必须 active、条目必须 active、签名权限证明尚未过期，正式发布指针须属于当前来源版本。维护者可以管理、处理和删除导入文档，但未获源端 readers 授权时无法读取正文。编辑本地 ACL 也不能绕过独立来源门禁。

同步领取、错误、暂停和移除先关闭该连接器全部文档的阅读；只有本轮全部追赶完成后恢复有效证明内的已授权阅读。内容变化在 I/O 前撤销旧发布指针，保持草稿，仍走已有安全检查、解析、索引和发布核验，绝不自动标记 clean 或发布。此保守策略会在同步期间短暂停读。

默认轮询 60 秒；源端已写入有效事件时，通常在下次轮询开始关闭旧阅读，完成后应用新授权。不是硬实时 SLA：调度/故障可能延迟；即使 Worker 停止，读取时数据库时钟仍使旧证明在其 valid_until 到达时失效，最大有效窗口 900 秒（含导出端允许的 30 秒时钟偏差时，最坏约 930 秒）。禁止通过成功重读延长旧证明。前提是导出者真实核验权限后签名；不把磁盘存在等同于上游仍授权。

列表、预览、下载、检索候选、模型调用前后与引用回查沿用当前门禁；预览与原文件在存储读取后再次核验，下载每段仍复核。推理期间撤权或证明过期会拒绝迟到结果。此前已交付给终端用户的字节无法追收。

移除连接器保留导入文档并关闭阅读，不批量物理删除。在同步详情中可分页查看仅含 ID/状态的导入记录、删除导入文档，继承 P1-14 保留期、审计和物理清理状态。

## 验证与范围

`npm run test:connectors` 使用隔离 PG schema、版本化开发 S3 和临时目录验证首导入、幂等重放、ACL/映射/动态群组、过期、缺页、哈希、内容变化、存储后事务回滚、显式删除、签名失败、背压、身份失效、暂停竞态、分批恢复、导出程序、独立 Worker 重启及移除保留。重排集成用隔离夹具验证来源过期的候选不会外发、推理中撤权使引用和结果失效。自动化桌面与 390px 浏览器覆盖添加、同步、完整校验、暂停、恢复、移除和删除保留文档。

真实部署仍需实际租户/资料库/受控目录、可信导出调度、签名密钥和成员映射，并按企业保留期配置进行联验。未实现 SharePoint、网页抓取、企业 OIDC、真实安全扫描器或正式发布工作流；模型质量和人工抽检待办继续保留。

本次验证记录：90 项基础/单元检查、234 项集成检查（含新增会话锁丢失接管场景）通过，合计 324 项；完整回归后对最终连接器及预览门禁修订另做专项复验。桌面和 390px 浏览器完成管理全流程，无页面异常。模型服务使用隔离夹具，目录为临时虚构资料，未修改真实企业来源。
