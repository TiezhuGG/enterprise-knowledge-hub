# P2-06 检索实验台与配置发布

日期：2026-11-08（Asia/Shanghai）。实现资料库级策略草稿、真实检索对照、当前权限复核、受控启用及回答策略溯源。实验不默认影响正式请求。本项没有下载或部署真实模型，真实业务题集与真人质量验收仍待完成。

## 入口与配置

应用迁移 013 后，资料库“文档与上传”中的管理者可使用“检索实验台与策略发布”。继续使用现有嵌入/索引及本地重排配置；不新增远端模型地址或凭据输入。

```sh
npm run build
npm run db:migrate
npm run test:lab
```

草稿是不可变的 retrieval_strategy 版本，保存规范化参数与 config_hash。修改通过复制配置并保存新版本完成，不能覆盖旧版本。支持：

- mode：dense / lexical / hybrid；top_k：1–20；max_characters：500–16000。
- dense 的 min_score：-1–1；lexical 的 min_score：0–1000000。
- hybrid 使用 hybrid.dense_min_score / lexical_min_score、candidate_depth（1–80）、rrf_k（1–200）、allow_partial。规范化内部保留默认 min_score=.25，但混合模式不接受用它另设通道阈值。
- 本地 rerank 的 enabled/top_n/max_input_characters/failure_policy，以及 context.max_per_document。

不接受 query、kb_ids、模型 URL、模型凭据、来源路径或权限字段作为策略配置。查询与资料库范围属于本次运行，策略参数与运行状态分别保存。JSON 对象键顺序和省略默认值不会制造不同策略身份。

例如，只改变 top-K：

```json
{"mode":"dense","top_k":10}
```

混合与重排示例：

```json
{"mode":"hybrid","top_k":5,"hybrid":{"candidate_depth":40,"rrf_k":60,"dense_min_score":0.25,"allow_partial":false},"rerank":{"enabled":true,"top_n":15,"max_input_characters":1000,"failure_policy":"fusion"},"context":{"max_per_document":2}}
```

## 权限与实验隔离

创建/查看草稿、运行实验需要该库当前 manage/read。发布还需 write/publish。角色和资源授权每次从 PG 重查；管理身份不能使不可读文档进入实验，也不能默认读取其他管理者的报告。实验记录按执行成员私有，策略版本与发布历史按资料库管理权限共享。

对照固定为一个资料库当前可读、正式发布且扫描通过的语料。参考文档必须属于同一范围；私有、草稿、删除、源端撤权或过期资料均不能进入模型输入或语料统计。初版最多 50 份可见发布文档、5000 条收据；继承检索通道的字符、产物、时间及数量上限。

保存草稿、运行实验均不更改 active_strategy_id。候选请求通过内部固定配置路径调用同一套生产检索实现，不伪造通道分数，也不绕过三道授权门禁。API 不接受客户端伪造的 strategy_trace。

## 对照与报告

API 每次接收 1–10 个问题，每题最多 5 个预期文档。界面先提供单题对照与多预期文档，批量样本可通过同一 API 提交：

```json
{"probes":[{"query":"差旅报销审批","expected_document_ids":["实际可读发布文档 UUID"]},{"query":"资料中不存在的编号","expected_document_ids":[]}]}
```

基线为实验开始时该库已发布的策略；尚无已发布策略时，使用规范化内置请求默认值（dense、top_k=5 等）。基线和候选串行运行于同一授权范围。报告记录参数/版本、文档/版本/代际/片段定位、实际通道名次和 RRF 贡献、重排名次/原名次、明确降级原因与耗时。

有参考文档时，Recall 是检索覆盖的参考文档比例，MRR 取最早命中证据名次的倒数；空参考列表表示预期无证据，正确空结果计 1，否则计 0。报告保存逐题值与均值，不把分数解释为回答置信度，也不把耗时当作费用。重排服务报告的用量保留在运行元数据中，未报告费用保持未知。

通过门禁要求：至少一个正例参考样本、基线和候选均未降级、候选 Recall 与 MRR 均不低于基线。没有正式发布语料时拒绝实验；只有空参考/拒答样本的报告可以用于探索，但不能发布策略。排名退化、模型或重排回退不能被计为正常通过。少量样本通过只是技术条件，不代替真人核对业务效果、覆盖范围、延迟和成本。

运行前后复核完整可见语料、文档/索引二元组、权限版本、收据、成员角色和授权版本、词法/词典及本地重排配置。范围变化使实验失败，不能保存一个看似成功的迟到报告。源端授权证明到期后无需等待 Worker，旧报告和预览即因当前门禁失效而被拒绝。

报告不保存问题明文、原文、标题或片段正文，只保存 query_hash、必要定位与指标；实验来源按钮在重新核对报告范围后按当前权限读取片段，并在读完后再次复核。请在受控业务评测库保存样本原文用于复现，摘要不是原问题备份。

实验有持久 running/completed/failed 状态与稳定 Idempotency-Key。重复提交只回看已有运行，不重复调用模型。执行取消或失败不自动重发；进程中断后遗留运行在两分钟后被读路径标为失败，重做需明确的新 key。总运行预算两分钟，报告有效期一小时；过期报告不返回详情、不能预览或发布。过期行及历史保留的是治理元数据，不新增原文保留副本。

## 受控启用、历史与回退

发布者必须使用自己当前未过期且通过的报告，明确完成人工核对并提交至少 10 字说明（仅保存摘要）。服务端复核完整权限/语料指纹、当前基线版本及 config_hash，校验资料库 If-Match，再在同一事务写 active_strategy_id、KB 行版本、发布事件、审计和幂等结果。任意审计写入失败整体回滚，并发提交只有一个成功。

发布后新请求可使用该库策略。若当前策略或语料已变化，必须重新对照，不能拿旧报告覆盖新基线。回退旧策略也使用同一流程：选旧版本，对当前策略重新实验，再受控启用；没有跳过评测的强制回退入口。历史记录保留版本、前后指针、实验 ID、发布者、时间及核对摘要。

## 正常检索与问答的策略溯源

SearchInput 新增 strategy_mode：active（默认解析模式）或 request。active 对恰好一个资料库应用其已发布版本；该库尚无策略时保留请求参数。若一次选择多个库或全部库，其中有当前用户可见的已发布策略，则明确返回 STRATEGY_SCOPE_REQUIRED，要求选择一个库；不会猜测应应用哪个策略，也不会因隐藏库的策略泄露其存在。

普通检索界面保留“请求配置”试查，勾选“使用已发布策略”才使用库策略，并在结果中显示版本/摘要。流式问答增加资料库选择，默认使用该库已发布策略；检索/回答均返回实际 StrategyTrace，含不可变版本 ID、版本号、规范化参数和 config_hash。无已发布版本的请求也记录完整参数及摘要。

聊天在创建持久运行时就固定解析后的策略，后续发布不会改变正在生成的请求。回答、运行状态和历史都能看到本次实际版本；重新生成复用原请求的固定策略参数，但重新检索当前获授权来源。策略版本不授予历史资料阅读权。升级前已经存在的旧聊天不补造策略记录；过期或被限制的历史继续遵循 P1-14 隐藏规则。
