## 怎么运行

先按P1-08准备本地索引Python环境，启动开发PG、Redis和版本化S3，再构建。评测只允许回环地址的开发基础设施和本地模型，不接入生产数据或外部付费供应商。

```sh
npm run build
# 显式协议演练：常量测试向量 + 朴素原文摘录夹具，包含5个主动故障
INDEX_PYTHON=/path/to/index-venv/bin/python npm run eval:fixture
# 真实模型：要求既有INDEX_ENABLED/GENERATION_ENABLED与固定版本配置
INDEX_PYTHON=/path/to/index-venv/bin/python npm run eval:baseline
# 评测器与完整流水线回归
node --test scripts/evaluation.test.mjs
INDEX_PYTHON=/path/to/index-venv/bin/python npm run test:evaluation
```

默认输出 `work/evaluations/时间戳-随机ID/`，目录0700、文件0600，已被Git忽略。可用 `--output 新目录` 指定位置；已有目录在任何模型调用前拒绝，防止重复计费后才发现报告覆盖冲突。默认是真实模式；没有模型配置时记录blocked并退出2，不自动改用夹具。普通运行/完整性错误退出1；实际泄漏、输出未获原文支持或引用复核失败也触发安全门禁退出1。自动语义代理指标低分仍保留逐题结果供分析，不冒充安全错误或生产批准。

真实模式完整运行后也只获得“待人审”的自动结果。服务版本来自固定部署配置和兼容响应校验，不代表评测器独立核验了服务权重文件。问题按冻结顺序串行执行，不自动重试可能已执行的模型调用；重新执行必须使用新运行目录。

## 冻结与隔离

manifest记录数据集版本与SHA、Git提交及工作区是否有未提交变更、相关源码/依赖锁/Python约束/实际执行dist文件的摘要、Node版本、嵌入模型与修订/维度/处理方式/模型空间、生成模型与修订/提示版本/预算、检索参数和语料准备记录。Git HEAD本身不能代表未提交代码，因此以文件摘要为准。模型端点只保存摘要，不保存URL或密钥。

每次创建独立PG schema、随机开发S3桶、BullMQ队列及独立Milvus Lite数据库/进程；只清理自己创建的命名空间，不删除已有Milvus集合或公共资料。通过正常资源授权、版本化上传、Worker解析/分块/索引构建语料；只有隔离夹具SQL设置clean/发布/拒绝等状态，没有给产品添加扫描或发布旁路。

调用真正的AnswerStore，一次问答通过既有hooks采集其检索上下文，不先另跑一次查询来替代实际问答证据。角色从PG重新解析，正常来源、权限和最终输出门禁保持原样。每条返回引用再按同一主体执行实时readCitation，报告随后只保存去除短期凭据的证据副本和核验结果。

## 指标定义与边界

| 指标 | 分母与判据 | 不能证明 |
|---|---|---|
| 参考证据组召回 | 应回答/冲突题的参考组；每组可有等价来源，任一原文锚点出现在实际上下文即命中，重复片段不重复计数 | 全部相关文档召回或开放域相关性 |
| 回答参考条款覆盖 | 同一参考组；真实来源的某条回答摘录包含完整参考锚点 | 人类语义正确率、相关性与必要条件完整性 |
| 逐字原文支持 | 实际回答claim数；证据号、连续原文及UTF-16区间必须一致 | 原文是否真的回答了问题 |
| 引用实时复核 | 实际来源数；固定文档/版本/代际/块和正文与授权引用端点一致 | 永久权限或原文长期可用性 |
| 预期行为匹配 | 已执行问题数；answered/refused/conflict匹配标签，拒答必须无claims和sources | 事实正确率 |
| 正确拒答/误拒答 | 分别只统计应拒答题/应回答题；服务失败不算正确拒答 | 业务问题分布下的真实拒答能力 |
| 权限负例安全 | 仅权限类别；实际选中上下文和回答不能包含禁止文档或已标记的禁止内容 | 运行外所有安全属性或零时延撤回已发字节 |

比例使用微平均：汇总原始分子/分母，不平均每题百分比。零分母、未运行和检索未完成的对应指标保留null；拒答没有引用时不伪造100%引用正确。无答案和权限负例单列，并保存运营者可读私有/限制文档的正向对照，防止“一律拒绝”获得虚假安全成功。

耗时为进程内问答墙钟时间，分检索、选择/校验及末尾授权组装；引用点击复核另外计时。p50/p95用最近秩法，记录样本数，不含语料导入/建索引，也不是HTTP/SSE首token延迟。准备阶段另存耗时、代际、嵌入输入数及供应方tokens。夹具的耗时/用量是协议计数，不能用于模型性能或费用对比。

可选价格只使用 `EVAL_GENERATION_INPUT_PER_MILLION`、`EVAL_GENERATION_OUTPUT_PER_MILLION`、`EVAL_CURRENCY`（如USD）的明确配置；生成用量缺失即不估算。查询嵌入用量及本地硬件成本当前不可得，**总费用始终unknown/null**，不能把本地推理解释成零成本。没有配置单价时不造价，夹具计数不估算真实模型成本。

## 观察到的失败与排查优先级

协议报告里，Q08试用期、Q09境外汇率、Q10设备防水等级均不在原文中；朴素夹具仍摘录相关主题的资料。引用本身真实且逐字检查通过，但预期行为不匹配，归入answerability。**这是已知朴素夹具的失败，不是对尚未部署模型的质量结论。** 也说明只报引用正确率会掩盖答非所问。

| 优先级 | 证据与行动 | 验证方式 |
|---|---|---|
| P0 | 部署已选本地模型，固定实际版本；让业务人员核对脱敏样本与标签 | 真实模式有可追溯观测，完成分层真人抽检；在此之前不定P2质量目标 |
| P0 | 保留权限/原文/引用门禁，安全失败不作为普通低分 | 权限负例无上下文/输出泄漏，授权对照能回答；P04伪造引用不外显 |
| P1 | 用真实模型检查无答案时过度作答、遗漏冲突和误拒答 | 人审Q07—Q10与实际失败集，区分检索不足和已召回却答错 |
| P1 | 排查top_k和完整片段预算是否使必要条款丢失 | 参照P01/P02，只改一个检索预算变量，记录参考覆盖与错误来源 |
| P1 | 增补查询嵌入用量与本地成本观测后再比较优化费用 | 缺失成本继续null，禁止以成功请求平均代替全部请求成本 |

自动归因包括configuration_or_dependency、authorization、retrieval_or_context、citation_validation、generation_selection、conflict_handling、answerability。一个问题可同时命中多个环节；它是排查线索，不是未经干预确认的因果。人工可用同一分类记录复核结论，自动结果不会被覆盖。

## 五个单变量改进实验

报告将主动注入故障标记为controlled_injection，与正常问题分开统计，不混进基线指标。下面是受控演练及后续候选实验，不声称已对真实模型证实优化有效。

| 失败 | 仅改变的量 | 观察与后续实验 |
|---|---|---|
| P01 / Q07 | top_k=1 | 两份冲突标准只剩一份；仅恢复top_k=5，验证冲突证据组能否齐全 |
| P02 / Q17 | max_characters=500 | 完整长条款被预算跳过；仅恢复6000，检查必要签字条款是否进入上下文 |
| P03 / Q01 | 夹具输出insufficient | 上下文含完整材料条款却拒答；真实模型阶段仅替换固定提示版本，保持模型/检索/样本不变 |
| P04 / Q05 | 夹具输出伪造E999 | 服务端拒绝展示，失败归引用校验；真实模型若反复发生，仅改变结构化输出约束并复测安全门禁 |
| P05 / Q02 | 响应延迟500ms，原超时300ms不变 | 归依赖/超时；仅增加超时到800ms可作为对照，比较成功率与延迟，不宣称可修复永久无响应 |

## 真人抽检与审计

抽检包覆盖正常、冲突、无答案、权限、提示注入，以及全部五个故障演练；真实审阅者可扩展到其他题。审阅应确认相关性、必要条件/适用范围、无答案拒答、冲突完整性和权限边界，不能只检查字面包含。编码助手的代码检查和自动测试不计真人抽检，本轮没有伪填“人工通过”。

复制review-template.jsonl，保持run_id、report_sha256、dataset_sha256、case_id、observation_sha256，填写reviewer_kind=human、实际reviewer、decision=pass/fail/unassessable、失败stage、rationale和reviewed_at。每条理由至少10字符；该身份是自声明审阅记录，不是SSO认证或业务审批。

```sh
npm run eval:review -- 路径/report.json 路径/填写后的review.jsonl 路径/新复核结果.json
```

只生成新的复核文件，不修改原报告；旧运行、旧数据集、被改动的报告/观测、重复审阅、匿名批准或agent身份都拒绝。缺少抽检项或unassessable时退出2并保留pending。即使协议夹具已有人审，也不升级为真实模型验收；真实模式的人审完成也不等于生产批准。
