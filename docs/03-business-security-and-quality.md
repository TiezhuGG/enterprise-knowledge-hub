# 业务实现设计、企业治理与质量门禁

版本：0.1｜本文件描述未来实施规则；本轮未实现服务、存储或模型调用。

## 1. 三条端到端业务闭环

### 1.1 员工查制度

员工登录 → 选择工作空间 → 提问“出差住宿标准是什么” → 系统检索员工可读的已发布制度 → 回答附版本与页码 → 点击证据核对 → 点“有帮助/有问题”。

验收关键点：同一句问题，不同岗位可获得不同授权资料；查不到证据明确说明；离职/撤权后无法通过旧链接读取正文。答案只说明资料范围和时效，不宣称掌握整个企业的一切信息。

学习点：RAG 的主要工程问题是“能否拿到正确、当前、获授权的上下文”，不是单纯编写一条更长提示词。

### 1.2 运营更新知识

知识运营上传制度 v3 → 解析预览 → 检查表格与来源定位 → 执行小型回归评测 → 审核发布 → 当前引用切到 v3 → v2 保留版本记录但不再作为默认检索来源 → 失败可回滚 active_generation。

验收关键点：索引未就绪不提前发布；相同文件重复上传得到可解释结果；任务失败重试不产生重复片段；回滚同时恢复文档版本与匹配的检索配置。引用旧版本时明确“历史版本”，并检查当前访问权。

### 1.3 Agent 跨资料排查

用户问“项目星河依赖哪些产品，变更影响谁” → 意图路由选择关系检索 → 图工具得到有来源路径 → 补查原文 → 输出关系说明与引用 → 若建议修改知识，只创建变更草稿 → 进入审批 → 审批后以幂等方式发布。

验收关键点：工具超时可终止；不能任意执行查询；图路径每一跳有可读来源；批准动作与实际执行动作完全一致；重复恢复不会二次发布。

## 2. 角色与访问策略

角色负责“能做什么”，ACL 负责“能看哪些资源”，密级负责“可送到哪种模型、是否可导出”。三者取交集。P1 使用 allowlist 与默认拒绝，不提供显式 deny 记录；后续如增加 deny，必须统一实现显式拒绝优先并迁移评测集。Workspace Admin 可管理配置，但默认不绕过独立受限知识库 ACL；紧急访问必须使用组织明确配置的 break-glass 流程并审计。

| 能力 | 员工 | 知识运营 | 工作空间管理员 | 审计员 |
|---|---|---|---|---|
| 查询获授权知识、查看自己历史 | 是 | 是 | 是 | 根据资源授权 |
| 上传/维护获授权知识库 | 否 | 是 | 需资源写权限 | 否 |
| 发布/回滚知识 | 否 | 被授予发布权限时 | 被授予发布权限时 | 否 |
| 管理成员、角色、模型、预算 | 否 | 否 | 是 | 否 |
| 查看审计元数据 | 否 | 自己的操作 | 工作空间范围 | 只读审计范围 |
| 查看所有文档正文 | 否 | 否 | 否，仍受 ACL | 否 |
| 生产高风险审批 | 否 | 被指定审批者 | 被指定审批者 | 否 |

组织映射用稳定的身份提供方 subject/group ID，不能只靠可能重名的邮箱/显示名。租户由已验证会话绑定，切换工作空间重新判断成员关系。外部 API Key 绑定服务主体和工作空间，不能把管理员个人权限原样转移给它。

## 3. 安全边界与攻击面

| 边界 | 典型失败 | 设计控制 | 验收样例 |
|---|---|---|---|
| 文件导入 | 宏、解析器漏洞、压缩炸弹 | 隔离解析、类型嗅探、大小/时间/展开比限制、补丁 | 伪装扩展名与超大解压样本被隔离 |
| 网页连接器 | SSRF 读取内网服务 | 域名白名单、DNS/IP 校验、重定向复检、禁止元数据地址 | 127.0.0.1/私网重定向不可达 |
| 知识正文 | 提示注入“忽略规则并泄密” | 正文只作数据、来源标记、工具层强校验 | 恶意文档不能扩大工具和资源范围 |
| 检索 | 跨租户、越权缓存命中 | 预过滤 + 真相源复检，缓存含 actor/policy_version | 租户A提问不返回租户B标记字符串 |
| 图谱 | 路径通过隐蔽节点泄露关系 | 节点/边/来源授权一致，受限聚合 | 隐藏部门关系无法被路径推断展示 |
| 模型出站 | 敏感正文发送错误供应商 | 按密级选择获准路由、脱敏、禁用未批准 fallback | 私有文档遇主模型故障不转公网 |
| 前端呈现 | LLM 输出 HTML/XSS/恶意链接 | Markdown 净化，禁原始 HTML，链接协议过滤 | 脚本与 javascript URL 无法执行 |
| 工具写操作 | 重试导致重复执行、审批后改参数 | 幂等键、payload hash、过期校验、最小凭据 | 审批后的参数变化返回冲突 |
| 日志与追踪 | 密钥、全文、个人信息泄露 | 默认元数据、字段脱敏、分权和保留期限 | 随机抽日志无完整 token/正文 |

提示注入不能仅靠提示词完全消除。权限控制必须在确定性服务端和工具层执行；模型建议永远不是授权证据。知识内容、网页内容和检索结果中的指令不能升级为系统指令。

## 4. 状态机与一致性

### 文件生命周期

uploaded → quarantined/scanning → parsing → chunking → indexing → ready_for_review → published → archived/deleting → deleted。

阶段失败转 failed，保留失败 stage、可读错误码、attempt 和 retry_at；重试从最近可重入阶段继续。取消是 cancel_requested → cancelled，Worker 在安全检查点响应。索引结果只有在发布门禁通过后可见。

### 运行生命周期

queued → running → waiting_approval / succeeded / failed / cancelled / timed_out / budget_exceeded。终态只允许幂等读取；重新运行产生新的 run_id 并记录 parent_run_id。SSE 连接断开不等于取消任务；用户“停止”调用明确取消接口。

### 发布与并发

知识库、Agent 定义、模型路由、检索配置都有版本号。更新携带 If-Match/ETag；版本不符返回 412 并提示比较差异。运行创建时冻结配置引用，不能运行到一半悄悄切到另一版模型或提示词。撤权与删除优先级高于冻结配置，仍须立即阻断后续访问。

### ACL 变化与缓存

ACL 更新递增 policy_version，失效相关缓存和搜索会话；输出前复检；引用读取重新鉴权。已在用户屏幕上显示的数据无法远程“收回”，产品需明确这一技术边界；撤权保证后续服务端访问被拒。不得承诺清除用户已经下载的文件。

## 5. 评测框架

先建 100–200 题基准集：精确事实 25%、语义同义 20%、多文档比较 15%、拒答/缺资料 15%、权限与攻击 15%、关系多跳 10%。试点业务若不同则调整比例。每题包括问题、角色、允许范围、参考答案要点、证据 chunk/version、拒答期望、难度、业务负责人。数据集拆开发集与锁定验收集，避免根据验收集反复调参。

| 维度 | 衡量方式 | 试点候选门槛（须校准） |
|---|---|---|
| 检索召回 | Recall@10：标注相关证据的覆盖率 | ≥0.85；按题型报告 |
| 排序 | nDCG@10、MRR，保留逐题结果 | 相对向量基线改善且无关键题退化 |
| 答案正确 | 业务专家按事实/完整性/时效打分 | 关键制度题正确率 ≥90% |
| 引用支持 | 引用可打开且能支持关联句子 | 支持率 ≥95%，定位可用率 ≥99% |
| 拒答 | 无证据应拒答，具备证据不误拒 | 分别报告召回与误拒，不能只算总准确率 |
| 权限 | 跨租户/跨ACL/旧缓存/图路径探测 | 固定安全集零泄露；不声称证明绝对安全 |
| Agent | 完成率、工具调用数、恢复重复副作用 | 非法工具零成功，恢复无重复写动作 |
| 性能 | 并发20，稳态1QPS，问答输出≤800tokens | 检索 P95≤2秒，首段 P95≤5秒，总时长 P95≤20秒 |
| 稳定性 | 试点成功请求/有效请求 | 月可用性目标99.5%，计划维护另定义 |
| 成本 | 每次成功回答 tokens/调用/金额 | 由批准模型报价与业务预算设门槛 |

这些是验收候选值，不是当前能力。LLM-as-judge 用于辅助定位，必须用人工样本标定，并保留模型与 prompt 版本。比较实验应冻结语料快照、ACL、题集、模型、chunker 与候选配置；一次只改关键变量，按题目做配对比较，报告样本量与不确定性。

## 6. 观测、故障与降级

每次 run、索引 job、工具调用传递 trace_id。记录阶段耗时、候选数量、过滤后数量、token、费用估计、错误码与配置版本，正文默认不记录。用户页看友好状态；运维页看技术摘要；详细调试仅限授权人员且同样受文档 ACL 约束。

| 故障 | 用户体验 | 系统动作 |
|---|---|---|
| embedding 服务不可用 | 新文件显示等待重试；既有知识可查 | 限次指数退避，断路器，死信与人工重试 |
| 向量服务不可用 | 如已配置独立词法后备可展示降级，否则明确失败 | 不假设同一 Milvus 内 BM25 能在实例宕机时存活 |
| 图谱不可用 | 提示关系分析暂不可用，可返回普通文档证据 | 不伪造图路径，不强制所有请求失败 |
| reranker 不可用 | 允许按已批准策略用融合排序并标记 | 观测质量影响；关键场景可拒绝降级 |
| 生成模型不可用 | 保留已找到的证据，提示重试 | 仅切到同等数据边界的获准模型 |
| 队列积压 | 展示排队与最近成功时间 | 按租户公平调度，暂停低优先级重建 |
| 权限服务/真相源不可用 | 暂不可访问 | fail closed，不用过期权限缓存放行 |
| SSE 断开 | 重新连接并恢复已保存事件 | 有界重放；超过保留期读取最终结果快照 |

## 7. 备份、恢复与数据保留

PostgreSQL 备份 + WAL/PITR、对象版本与校验清单、配置导出必须可恢复；索引可以重建，也应根据恢复时间目标选择快照。Redis 的丢失不应造成永久漏任务，Outbox 与周期 reconcile 能补偿。

试点候选目标：元数据 RPO≤15分钟、核心服务 RTO≤4小时；完整索引恢复另测且不承诺也在4小时内。每季度在隔离环境恢复，验证文档数/hash、版本、ACL、引用和标准问题。备份不是恢复能力，必须留演练证据。

默认保留期建议待企业确认：问答记录90天、运行事件30天、审计180天；日志更短、备份按轮换保留。用户删除会话与管理员保全策略的冲突在设置页说明。删除源文件后排队清理对象、索引、图事实、缓存和派生摘要；备份内数据按保留期自然失效，并明确不能即时逐条物理擦除所有离线备份。

## 8. 发布门禁与回滚

每次发布必须完成：领域/API 契约检查；接入幂等与失败恢复验证；ACL 对抗集；质量固定集；负载测试；迁移/备份/回滚演练；模型路由与成本限制检查。UI 无障碍、键盘操作和表单错误同属验收。

发布采用试点空间灰度 → 10% 合格用户 → 扩大。发现权限越界立即关闭相关检索/工具并回滚；质量下降回滚检索/模型配置版本；数据库迁移用 expand/contract，不能假设所有迁移可自动反向执行。上线负责人记录发布ID、变更、证据、监控窗口和回退方案。

## 10. 面向学习者的完成定义

每一项任务结束时，要能回答：这个组件解决哪个业务问题；如果拿掉会发生什么；它信任哪些输入；如何证明正确；失败时怎样恢复。提交一页学习记录，含概念、自绘流程、实验结果、一个失败案例和复盘。把“功能跑通”提升为“能解释、能验证、能恢复”。
