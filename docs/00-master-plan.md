# 知衡 · 企业级知识库项目总计划

设计基线 v0.1｜2026-11-06｜项目代号 enterprise-knowledge-hub

## 1. 项目一句话

建设一个**有权限边界、能追溯证据、可持续更新、可评测优化**的企业知识平台：员工自然语言查资料，知识运营治理内容，管理员控制模型与数据边界，开发者通过标准 API 集成；在稳定 RAG 之上逐步学习并引入图谱和 Agent。

本次交付到“设计可评审、任务可执行”的阶段，不实现服务、前端应用、数据库或真实模型调用。UI 是静态高保真设计稿，页面与状态映射可作为之后开发的规格。

## 2. 参考图如何落地

用户提供的参考图包含 NestJS、Milvus、Neo4j、大模型与 Agent，作为技术方向保留。需要调整实施次序：先把文档接入、权限、引用和评测做好，再上 BM25+向量混合召回，再评估图谱收益，最后给 Agent 有限工具选择与审批能力。

原图中“向量检索+图谱检索”是增强层；首个企业级检索基线还需要关键词检索，才能可靠处理制度编号、产品型号和精确术语。Agent 位于编排层，负责选择受控流程；它不替代身份验证、事务或业务规则。

## 3. 设计假设与待确认事项

| 项目 | 当前默认 | 如何确认 |
|---|---|---|
| 用户与规模 | 单企业100–500员工；多工作空间 | P0 访谈、账号与组织清单 |
| 首个试点 | 制度/产品/研发知识；先选其中一个部门 | 业务 owner 提供高价值问题 |
| 数据量 | 1万份文档、20万片段 | 对样本按格式统计页数与切块分布 |
| 部署 | 企业内网/私有环境；允许经过批准的模型API | 数据安全负责人确认密级与路由 |
| 技术团队 | 4人：产品/体验、前端、后端、AI/检索；运维安全兼职支持 | 明确真实人力后重排任务 |
| 学习者基础 | 能理解Web、HTTP与基本TypeScript；可边做边学 | P0 做术语与基础知识自查 |
| UI | 简体中文、桌面优先、移动端查阅 | 角色访谈与设备数据 |
| 项目名 | 知衡 · 企业知识中枢 | 可在正式立项时改名，不影响技术设计 |

以上默认让计划可执行，不意味着用户已确认全部业务假设。影响数据边界、模型外发、组织权限的事项在实施对应功能前必须形成明确决定。

## 4. 产品价值与衡量

- **员工效率：** 从寻找多份资料到获得可核对的答案，观察解决问题时间、重复提问与人工转接率。
- **组织记忆：** 每份知识有 owner、版本、有效期和来源；观察过期内容占比、更新延迟和认领覆盖率。
- **可信使用：** 引用可定位、缺证据能拒答、权限不被绕过；观察引用支持率、误答、误拒与越权测试。
- **可运营的AI：** 每次模型与工具调用可追踪、有预算、有质量对比；观察每次成功回答成本与回归趋势。

效果采用试点前后对比，不能只统计问答次数。给人工查找时间建立基线，经过业务抽样复核再判断收益。

## 5. 交付阶段与里程碑

| 阶段 | 结果 | 关键门禁 | 大致顺序 |
|---|---|---|---|
| P0 需求、设计与基准 | 场景、资料样本、权限规则、32屏设计、测试集 | 业务与技术评审；未知项有owner | 前2周 |
| P1 基线RAG | 登录/ACL、文件接入、向量检索、带引用问答、最小评测 | 正确版本与来源、拒答、无越权 | 第2–6周 |
| P2 混合检索生产化 | BM25+向量+融合+重排、连接器、调试、版本治理 | 比基线的效果改进、时效与失败恢复 | 第6–9周 |
| P3 图谱与有界Agent | 有来源图谱、受限工具、状态、审批、恢复 | 图谱增益、调用边界、幂等恢复 | 第9–12周 |
| P4 企业试点与上线 | 可观测性、压测、备份恢复、灰度、运维手册 | 完整质量、安全、容量与回滚证据 | 第12–16周，预留到18周 |

阶段可以有少量重叠，例如前端根据契约开发、AI同学提前做检索实验；数据权限与引用主链是关键路径，不应被图谱界面或Agent动画挤占。14–18周是有经验4人团队的初步估算，不是上线承诺。详见任务文件中的人日、有效投入与风险缓冲。

个人学习者先完成“单业务域、托管基础设施、单企业试点”的核心版本，5–8个月仅是这一缩小范围的学习估算；完整企业范围由单人交付通常更久。学习时间、真实数据质量和基础设施条件都会改变周期。

## 6. 范围：先形成闭环，再扩展

**首个可用闭环：** 登录→选空间→建知识库→上传文档→检查解析→发布→提问→查看引用→反馈→运营整改。后台至少包含成员、资源权限、模型配置、审计与基础运行状态。

**后续增强：** 增量连接器、混合调优、图谱实体与关系治理、有界 Agent 工具、审批恢复、多方案评测、精细预算、灾备演练。

**暂不纳入首轮实施：** 通用自主办公Agent、任意数据库写入、任意网页抓取、跨企业公开分享、完整低代码平台、原生移动App、视频理解、自动训练基础模型。后续可进入需求池，但不能默认为已包含。

## 7. 文件阅读路线

| 文档 | 解决的问题 | 建议读者 |
|---|---|---|
| 01 产品与体验 | 谁用、为什么用、业务怎么闭环 | 全员 |
| 02 架构与选型 | 组件如何协作，为什么这样选 | 架构/研发/学习者 |
| 03 业务安全与质量 | 如何避免越权、错误与不可恢复故障 | 研发/产品/运维 |
| 04 数据与API | 资源、状态、接口与错误怎么约定 | 前后端/AI |
| 05 任务与学习 | 下一步做什么、怎样完成与学会 | 项目执行者 |
| 06 UI规格 | 每屏布局、交互、角色与异常状态 | 产品/设计/前端 |

## 8. UI 信息架构

32个主界面按六组组织：

1. **进入与发现 UI-01–07：** 登录、空间、总览、问答、证据、历史、搜索。
2. **知识治理 UI-08–15：** 知识库、配置、文档、上传、处理、版本、连接器、同步。
3. **检索与图谱 UI-16–18：** 调试、图谱、实体纠错。
4. **Agent UI-19–22：** 列表、编排、运行、审批。
5. **质量 UI-23–25：** 评测集、方案对比、反馈整改。
6. **组织与运维 UI-26–32：** 成员、权限、模型、密钥、审计、监控、设置。

本轮为所有主界面生成画面，同时补充公共空/加载/失败/无权限状态、关键弹窗及移动端参考。画面中的按钮表达预期交互，交互逻辑详见规格；它们不是已经接通的应用。

## 9. 学习方式：从知识到证据

每一阶段都执行“理解概念 → 对照业务 → 小实验 → 观察失败 → 写验收证据 → 复盘”。Agent学习不是背框架API：先理解模型只能根据上下文生成，再理解检索与工具怎样补足信息，最后学习状态、预算、权限、审批和恢复怎样约束行动。

每周建议一次60分钟设计复盘、一次30分钟可运行成果演示（未来开发阶段）、一次学习日志回顾。每次任务提交说明解决的问题、测试证据、限制与下一步。完成任务卡上的练习才算完成对应学习目标。

## 10. 设计基线的使用规则

当前所有功能状态都是“已设计/待实施”。API样例是契约草案，不代表接口已可请求；图中组件不代表已安装；界面指标不是实测；Git提交表示设计版本，不表示应用发布。

设计变更按“原因→影响页面/API/任务→新验收标准→ADR”记录。优先保留可验证的简单方案；只有业务样本和评测结果支持时，才增加图谱、更多Agent或更多基础设施。
