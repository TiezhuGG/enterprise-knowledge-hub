# P1-14 删除、撤权与版本一致性

日期：2026-11-07。实现文档删除同步屏障、永久删除标记、可恢复的物理清理、历史正文保留期及界面处理记录。迁移010新增生命周期记录，并为既有不可变表增加严格限定的一次性脱敏转换；原文SHA、版本身份、责任人和终态仍不可改写。

## 生效时间与副本

| 位置 | 逻辑失效 | 物理清理 |
|---|---|---|
| PG文档与发布指针 | 删除事务提交时设deleted、清空发布指针并写永久tombstone | 保留最少身份、摘要、版本与审计；清理标题及原文件名 |
| S3原文、解析与分块 | 每次读取重新校验文档、当前发布版本及权限 | 保留期后枚举确切原文key、各版本专属parsed/chunks命名空间，删除全部对象版本与delete marker并复查；包含无PG收据的迟到对象 |
| PG结构块、分块与来源 | 读取及引用门禁立即拒绝 | 清理派生行、向量收据与处理检查点；不覆盖原版本身份 |
| Milvus向量 | 搜索候选必须通过PG当前发布代际与权限检查 | 按tenant+generation精确删除，强一致查询确认；不会删共享collection |
| 嵌入缓存 | 当前来源门禁使缓存无法成为授权依据 | 删除该文档相关hash且无其他有效代际引用的缓存；保留其他有效文档共享的条目 |
| 聊天回答、依赖和引用 | 每次历史读取/SSE批次/引用定位重新授权；来源变化时隐藏回答 | 到期、删除会话或来源清理时，擦除问题、回答、依赖摘录、事件与反馈，保留运行身份/终态与purge记录 |
| 纠错说明与内部备注 | 文档失效后纠错读取也不可用 | 物理清理阶段固定替换原反馈与事件正文，清除核验/整改备注和闭环证据 |

“立即”以PG事务提交为顺序边界：提交后开始的受保护读取不会使用旧授权。提交前已通过授权的读取可能完成；已经发送给客户端的字节不能撤回。撤销成员/ACL权限不删除其他有效成员的共享资料，PG当前身份、ACL版本和发布指针始终是真实门禁。旧版本不等于当前证据：切换发布指针会使旧引用/历史回答受限；有编辑权的原文件历史访问仍遵循版本接口策略。

## 删除与任务恢复

DELETE在同一事务内核对当前身份、有效delete权限和If-Match，写永久tombstone、清空发布指针、取消queued/running/retry_wait/waiting_dependency摄取任务，结束相关运行中聊天，登记唯一清理任务、幂等请求及审计。旧队列投递无法领取，迟到处理结果不能提交，也不能重新发布tombstoned文档。无权限的幂等重放仍被拒绝。

所有原文件、解析、分块、嵌入及向量写入在I/O前登记storage_write。登记和依赖摘录捕获都持有当前文档门禁；删除提交后不能新登记写入。已经登记的远端操作允许收敛，但清理遇到running/unknown必须停止为waiting_dependency，不能以PG任务已取消代替远端完成证明。嵌入调用的费用未知状态仍按原有台账处理，清理不会重试模型。

清理器独立于BullMQ和模型服务轮询PG。每个任务持有PG会话advisory lock，跨外部I/O维持互斥；进程断开锁自动释放，下一实例可重新领取running任务。每项目标在执行前持久化，重复执行幂等；外部失败保留pending项，30秒后自动重试，最多5次后failed。有权维护者可人工重试；not_before不会因此提前。清理状态、阶段、尝试次数、逐项计数、事件可追踪；对外不返回对象key、桶、凭证或内部路由。

新对象绑定桶/地址/region指纹，每次对象写入另记实际路由，新向量代际绑定Milvus地址指纹。清理连接的存储与绑定不符、旧记录无绑定或存在未核对的其他写入路由，均停在waiting_dependency，不能把错误位置的空列表当作完成证据。`bind_legacy`只补缺失绑定，不覆盖已有绑定；它是维护者已经核对原存储位置的声明。旧集群迁移、复制或更换bucket不能仅靠该动作宣称清理原存储，需要恢复原配置核对并清理；当前实现不提供跨集群迁移流程。

`reconcile_writes`要求维护者停止旧进程、核对未决请求并填写说明；记录至少静置五分钟，才允许将running/unknown标记reconciled。静置不能代替远端核对。不同对象路由的已确认写入也必须先核对：若确为同一后端代理，记录核验；若为独立存储，先清理其他位置的副本，再提交收敛声明。旧协议的运行中摄取会留下legacy未知写入阻断；升级前还应排空旧API上传请求。动作审计记录当前操作者及说明摘要，避免审计中再次保存可能复制自原文的正文。

## 保留策略与开关

```dotenv
LIFECYCLE_CLEANUP_ENABLED=false
LIFECYCLE_DELETE_RETENTION_HOURS=168
CHAT_HISTORY_RETENTION_DAYS=30
LIFECYCLE_POLL_MS=1000
```

这些是开发默认值，尚不代表企业已批准保留政策。默认不运行破坏性物理清理。删除保留期在任务创建时快照；聊天期限在创建运行时快照，既有聊天迁移为created_at+30天。之后修改配置不追溯延长/缩短旧记录。历史读取即使清理器关闭，也必须遮蔽到期正文，返回expired；无回答、引用或反馈，禁止重新生成。后台启用后执行物理正文清理，删除会话的正文也会被清理。

启用清理前，应用迁移010、部署同版本API/Worker、停止并排空旧协议写入进程，核对实际桶/向量位置及企业保留政策。历史旧记录可以在核验后补齐绑定；缺失依赖会明确保留阻断。对象版本清单每个命名空间最多10000项，超限或供应商Object Lock/服务故障会留下失败记录而非误报成功。物理完成覆盖本应用配置的活动存储；备份、外部导出及客户端已保存内容需要独立的保留/销毁流程。

## API与界面

所有路径有认证；写操作要求Origin/CSRF，响应private/no-store。

| 方法 | 路径 | 行为 |
|---|---|---|
| DELETE | /documents/:id | If-Match、Idempotency-Key；202，返回清理任务 |
| GET | /knowledge-bases/:id/cleanups | 当前有效read+delete权限先过滤，再游标分页 |
| GET | /cleanups/:id | 重新核对已删除文档的当前ACL，返回状态、项目计数及最近50条事件 |
| POST | /cleanups/:id/actions | 当前有效manage权限，action为retry/reconcile_writes/bind_legacy，note至少10字 |

“文档与上传”提供删除确认，确认使用打开对话框时的ETag；并发变化返回412，需刷新重新核对。删除后可从“删除与清理记录”查看结果、阻断原因及核对动作。确认写入收敛/旧存储绑定是有责任人的运维声明，不冒充自动验证。
