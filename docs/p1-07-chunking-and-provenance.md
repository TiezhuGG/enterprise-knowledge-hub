# P1-07 分块与溯源元数据

## 运行与升级

按 [开发说明](development.md) 和 [解析说明](p1-06-document-parsing.md) 启动 PostgreSQL、Redis、私有版本化 S3，执行 `npm ci`、`npm run build:packages`、`npm run db:migrate`，再重启 API/Worker/Web。新增迁移005，旧迁移的校验和不变。

迁移和 Worker 的受控恢复只处理明确等待分块、已保存对应解析产物且未取消的任务。`CHUNKER_ENABLED=true` 默认启用；设为 false 时停在 awaiting_chunker，再启用会恢复任务。存在固定解析结果时可在 PARSER_ENABLED=false 下继续分块，不重新读取/解析原文件。失败、取消或 awaiting_indexer 任务不被恢复器重新排队。

业务 Worker 读取检查点后，从固定 S3 VersionId 读取解析 JSON 并验证摘要；不重新调用 API，也不接受用户传入的策略脚本、任意路径、身份或网络地址。

## 首版策略

策略版本为 `structure-chunks-v1`，其 policy.strategy 为 `structure-v1`。参数与算法一起冻结到版本，运行时不允许通过修改环境变量悄悄改变同一版本的结果。后续调参/算法变化需新版本与迁移。

| 规则 | 当前行为 |
|---|---|
| 长度 | 检索文本最多1200个 UTF-16字符，包括最多240字符的章节导航和分隔符；不是模型 token 数 |
| 标题/段落 | 保留章节边界，同章节相邻短段落/列表项合并；标题仍是可定位的原结构内容，可能产生短片段 |
| 长段落 | 优先在后半段的句末/空白处切分；只有超长单段切分才采用最多120字符重叠；不拆 UTF-16代理对 |
| 代码 | 独立成块，超长时同样限制长度；仅作为文字保存和显示 |
| 表格 | 按完整行分组，每组重复全部显式表头，保存原行范围与表头/正文引用；不拼接跨页表格 |
| 超宽表头/长行 | 无法连同表头放入长度预算时明确失败，要求简化原表后上传新版本；不截断单元格或丢弃行 |
| 不可靠结构 | 表头未知不猜测；合并单元格与章节导航截断均记录质量提示，保留解析阶段提示 |
| 页眉页脚 | 不进入结构策略检索片段，统计排除数量；在原解析产物中完整保留 |
| 资源 | 每版最多10,000块、20 MiB产物；分块计算15秒协作式预算，定期让出事件循环以处理心跳/取消 |

分块在 Worker 内对已限额的解析结构计算，不执行文档代码，不调用外部模型。协作式预算不是操作系统沙箱，原文解析隔离与限制见 P1-06。单次整体执行仍受租约和 INGEST_DEADLINE_MS 约束。

## 可追溯记录

每块包含稳定 ID、顺序、正文、用于检索的章节前缀+正文、两个精确 SHA-256、标题路径和来源引用。ID绑定租户、原文版本、固定解析产物摘要、分块器版本/策略、顺序和正文摘要；相同版本重试得到相同ID，不同版本有独立ID。ID不依赖文件名。

provenance固定 tenant/kb/document/version/version_no、source_asset_id、原文SHA、解析器版本、解析产物SHA。每条 span 固定 parsed_block ID/顺序、该块**解析文字内**的 UTF-16偏移 `[start,end)` 和原文定位；表格额外区分 table_header/body，保存0起始半开行范围。解析文字偏移不等于原 Markdown/XML/PDF文件字节偏移，须先定位解析块，再按其原文位置核对。PDF保留真实页码/坐标，DOCX保留part/段落/表格位置，不伪造页码。

permission_source只是 `current_document_acl` 的资源引用，**不保存可长期信任的角色/allowlist快照**。读取与未来检索必须按当前租户、成员及文档权限复核；不能把产物内身份字段当作授权。API从认证会话与数据库解析主体，草稿/待扫描版本继续沿用既有可见性规则。分块不把 scan_status 从 pending 变为 clean，也不意味着已经发布。

PG保存 chunk_manifest、knowledge_chunk 与 chunk_source 元数据；外键把每条引用约束到同租户/同文档版本/同解析版本的结构块和原文摘要。三个新表拒绝 UPDATE。全文只保存在私有、版本化的 S3 JSON，PG记录固定对象版本与摘要，前端不获得S3 key/版本/凭据。

## 恢复、取消与存储边界

解析、分块分别保存检查点。已提交的解析产物可在 Worker 重启、人工重试和分块恢复时复用；重复队列交付不会建立重复记录。S3派生产物按内容摘要命名，同内容重试复用固定对象。提交前后都复核当前写权限、成员状态、源安全状态、租约/轮次、取消和截止时间，旧 Worker 的晚到结果不能建立可用 manifest、检查点或推进终态。

S3写入与PG提交之间中断、取消或撤权可能留下未引用派生产物。当前上传清理器不处理 parsed/chunks前缀；生产需按已引用的固定对象版本和保留期增加垃圾回收，不能直接对整个前缀设过期删除。派生存储也需计入生产容量规划；当前单版输出限额不是全租户派生存储配额。

## API与界面

| 接口 | 行为 |
|---|---|
| GET /api/v1/documents/:documentId/versions/:versionId/chunks | limit/cursor签名分页，返回当前版本manifest与片段 |
| GET /api/v1/documents/:documentId/versions/:versionId/chunks/:chunkId | 精确片段、固定来源及权限资源引用 |
| GET /api/v1/documents/:documentId/versions/:versionId/parsed?block_id=:id | 定位该版本的原结构块，复用现有预览权限 |

列表游标绑定租户、当前成员/授权版本/角色、文档版本、分块器版本与页大小。每次访问重新鉴权，未知/无权资源404、未就绪409；游标不能跨主体/版本/过滤重放。单块查询不能用别的版本路径读取旧块。

“分块预览”显示真实片段数、精确重复比例、重叠字符数、标题上下文、表格和来源范围；可加载后续片段，点击“查看结构原文”打开确切解析块，再按独立 download 权限下载固定版本原文。较长表格首屏显示50行，可展开。预览不提供已完成检索/索引的假入口。

## 重复统计与策略比较

exact_duplicate_chunks = 总片段数减去正文 NFC归一化/连续空白折叠后的唯一 SHA数，duplicate_ratio 为其占比。不会据此删除证据或跨权限/版本复用记录。overlap_characters只统计超长正文窗口的重复范围；重复表头、章节前缀单独对待。retrieval_characters为实际检索字符串总长度，包含章节前缀和重复表头，不是嵌入调用次数或费用。

可运行 `npm run compare:chunks -- --write` 重建 [样本对比](p1-07-strategy-comparison.md)。固定1200/120窗口和结构策略在同一自造制度样本、5个词面检索问题上比较片段量、字符量、重复与证据完整性。结果不代表语义召回率或问答准确率；真实向量检索和成本验证留待 P1-08/09 与业务脱敏语料验收。
