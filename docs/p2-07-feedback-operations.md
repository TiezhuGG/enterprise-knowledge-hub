# P2-07 反馈、知识缺口与运营闭环

资料库文档界面提供“反馈与知识缺口运营”；单资料库问答可通过“报告知识缺口”明确分享问题。原有赞/踩保持私有，不自动转成运营工单。用户必须确认分享并填写说明；管理者不能借此读取整段私有聊天。报告人仅查看自己的有效记录，内部处理说明、负责人账号及关闭证明仅向当前有权维护者展示。

## 工作流程

1. 报告人初步选择缺少资料、资料过期、检索错误、回答错误、权限问题或待分类。高优先级提交自动绑定当前有权管理和读取来源的负责人，无人可接手时拒绝提交；撤权后显示需重新分派。
2. 维护者人工分诊、分派或接手，记录处理依据。变更使用 ETag、幂等键和原子审计，旧页面不能覆盖新状态。
3. 知识补充沿用纠错、扫描、索引和显式发布流程。回归问题及预期文档必须人工审核；审批表仅保存问题摘要与文档 ID，不复制原文到永久题集，不自动训练模型。
4. 运行 P2-06 策略对照；只有当前负责人私有、未过期、问题与预期文档匹配、无降级且候选覆盖为 1 的报告能用于完成。策略必须已经启用，语料和权限指纹仍有效，且报告人当前能读取修复结果。模型运行期间工单变化会阻止迟到结果覆盖；显式重试复用已有实验。
5. 缺少资料或资料过期还要求已发布的新资料或较新版本。权限问题不能通过给空预期列表而宣称恢复；需要人工核验关闭或提供实际可访问证据。工单本身不修改 ACL。人工核验关闭与已验证完成分别展示，保留重新打开入口。

## 权限、保留与统计

所有读取、列表分页及统计在查询内先复核当前资料库、文档版本、扫描及来源授权；来源证明过期或撤权即隐藏，不依赖后台清理。只允许关联本人、单资料库且问题匹配的运行。关联来源删除、聊天删除/到期会立即隐藏工单，生命周期清理随后擦除问题、说明和事件备注；普通工单正文最多保留30天，关联聊天保留期更短时随之收紧。开启 `LIFECYCLE_CLEANUP_ENABLED` 才执行后台物理清理。哈希、资源 ID、状态和审计元数据保留；HMAC 使用服务器游标密钥，不保存明文问题到幂等记录。

统计只覆盖当前可读且未过期工单，按类别、状态、高优先级、需重新分派、重复组和平均关闭周期展示，不能当作全租户总数。重复是同租户/资料库内 NFKC、空白、大小写规范化后的精确 HMAC，相似语义不自动合并。合并仍需人工确认。关闭周期包含人工关闭和重复合并，统计提供样本数，不等同于修复耗时或质量提升。

## 开发与验收

先执行迁移014，再部署依赖新表的 API/Worker；旧迁移不改写。运行 `npm run test:feedback`。集成测试使用隔离 PostgreSQL、S3、Redis、真实 Milvus Lite 及受控嵌入/生成/重排服务；验证分享、私有队列、有效负责人、并发与幂等、审计回滚、人工审核、策略闭环、来源撤权与正文擦除。真实生成模型、安全扫描器、企业来源及真人质量抽检仍待联验，夹具覆盖率不代表真实模型效果。

## 十条虚构反馈分类练习

下表仅用于演练分诊，不是线上统计。

| 反馈摘要 | 分类 | 处理依据 |
| --- | --- | --- |
| 新员工问住宿证明，库内没有规定 | 缺少资料 | 请业务负责人补充并发布 |
| 问海外差旅补贴，只有国内制度 | 缺少资料 | 明确业务范围后补充 |
| 回答引用去年报销上限 | 资料过期 | 发布新版本并复核旧引用 |
| 回答仍是撤销的审批流程 | 资料过期 | 核对生效日期和替代版本 |
| 有现行差旅制度却搜到采购文档 | 检索错误 | 审核正例并对照策略 |
| 简称检索没有命中正确制度 | 检索错误 | 核对术语和候选召回 |
| 引用正确但回答错了适用对象 | 回答错误 | 核对上下文和摘录约束 |
| 把两个不同审批步骤混成一个 | 回答错误 | 审查证据组合和预期结果 |
| 部门成员无法查看本应可见制度 | 权限问题 | 找授权负责人核对当前权限 |
| 只说“不好用”，没有问题与依据 | 待人工分类 | 补充重现信息，不能直接训练 |

本演练优先修复“资料过期”：已有明确的新旧版本依据，发布修订后可同时纠正多个重复问题，并能通过当前版本和授权回归验证收益。实际优先级仍需结合有效反馈数量、业务风险与修复成本确定。
