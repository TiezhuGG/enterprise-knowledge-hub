# P2-01 词法检索与中文术语处理

日期：2026-11-08（上海时间）。新增独立BM25通道，复用P1-09的授权、确切发布代际、clean原文、完整收据、来源哈希与引用复核。默认仍为dense；不做通道融合、不直接相加分数。真实嵌入模型尚未部署，语义质量对照和人工相关性验收继续保留待完成状态。

## 选型与实现范围

采用本地CPU BM25（k1=1.2、b=0.75），在请求内对当前授权快照建立词项计数与文档频率。没有新增远程分词服务、模型调用或持久化正文索引，也没有升级现有Milvus 2.4依赖。此通道适合当前小规模基线，便于先验证精确编号、缩写与中文术语的收益；不是大规模常驻检索引擎或已经验收的生产吞吐方案。

当前范围上限：50份可见发布文档、5000个分块、32MiB分块制品、50万分词结果；查询最多64个唯一词项和8个引号短语。超过上限返回422或400，不截断授权语料后冒充完整BM25排名。两个通道都保留160个候选、top_k不超过20、相同的上下文预算和按检索内容哈希去重。5000是载入分块上限，160是排名后的候选上限。

每次请求重新读取并校验S3分块制品；不复用旧权限缓存。为避免撤权后仍用隐藏资料计算DF/平均长度，词法请求从读取制品到评分及证据组装持有PG来源锁。撤权/删除提交前可能等待该读取完成；提交后开始的新请求使用新权限。30秒取消边界与规模上限限制此基线；高频/大规模场景应另行设计带权限与版本绑定的物化索引，并测量锁等待，而不是直接扩大上限。

## 中文与领域术语策略

- 使用NFKC、ASCII小写与常见连接号归一化；保持原始摘录和位置不变。`Ａ－１００`可匹配`A-100`，但`A-100`、`A-1000`、`XA-100`是不同词项。
- 字母数字及内部`._+/#-`保留为完整编号，如`RS-485`、`SAML-2.0`、`API/v1`。查询中出现带数字/分隔符的字母标识时，候选必须精确命中至少一个此类标识；多个型号比较可以分别召回对应资料。
- 中文使用Node内置`Intl.Segmenter(zh-CN)`，先做版本化领域词最长匹配，再分词并去少量明确停用词。仓库初始词表是虚构企业场景示例，如采购审批、访问控制、差旅报销；不代表已经得到业务部门批准。
- 词表、分词版本与ICU版本随结果及报告记录，词表有SHA-256。修改词表须增加样本、复跑冻结对照并记录版本；当前没有让读者任意修改词表或从原文指令自动学习术语的入口。
- 不自动把SSO等缩写扩展成未核验的别名，不用模糊前缀把相近型号合并。未加引号的普通词项按BM25贡献排序；这不是所有词项都必须出现的布尔AND。
- 成对英文双引号表示归一化后的连续字面短语；编号仍检查完整边界。未闭合引号返回400。SQL、脚本和过滤表达式只作为普通查询字符，不执行。

## API与界面

`POST /api/v1/search`增加`mode: "lexical"`。省略mode保持dense。`min_score`在dense默认0.25、范围[-1,1]；lexical默认0、范围[0,1000000]，只返回正BM25得分。阈值只属于各自通道，禁止将BM25、余弦分数当作概率或直接相加。`meta.lexical`记录算法、分词/ICU版本和词表摘要。

搜索页新增“检索通道”，结果明确显示“BM25”或“相似度”，切换时清除旧结果。引用复核、版本原文件和正文位置继续使用原门禁。已有问答/chat API同样接受lexical模式并保持服务端证据校验；问答页面默认通道保持dense，本任务不自动切换或降级检索器。

词法通道本身不需要查询嵌入服务在线；但当前发布门禁仍要求已存在的ready代际和完整收据，不能把未处理或未发布的资料拿来补足词法结果。

## 冻结挑战样本与量化对照

[数据集](../evals/lexical-v1/dataset.json)及[锁文件](../evals/lexical-v1/dataset.lock.json)固定16份虚构原文、21题，分为型号编号、缩写、中文术语、短语、无匹配和权限负例。保留原P1-12的Q05/Q06（ZX-2400、ZX-2401）来源与原文摘要，并增加路线图要求的A-100/A-1000/XA-100挑战。它们是精确匹配的失败候选场景，不冒充已经观察到真实嵌入模型失败。

```sh
npm run check
INDEX_PYTHON=/path/to/python npm run test:lexical
INDEX_PYTHON=/path/to/python npm run compare:retrieval -- --fixture --output work/my-protocol-comparison
INDEX_PYTHON=/path/to/python npm run compare:retrieval -- --output work/my-real-comparison
```

对照器为两个通道使用同一隔离语料、成员、KB范围、确切发布版本、top_k和字符预算，只改变通道及其阈值。输出逐题来源、版本/代际/分块、摘录、分数、耗时、错误、Top1、Recall@5、MRR及权限安全检查；多来源题的Recall按参考文档覆盖比例计算。基础设施错误单独计数，指标留空；缺失真实模型时退出2、记录blocked，不自动换成夹具。输出目录必须为空，避免混淆旧运行。

[协议观测](../evals/examples/p2-01-protocol/report.md)中，真正运行的BM25在15个正例上Top1和Recall@5均为15/15，6个负例均为空；型号比较题覆盖两份型号资料。两个通道均未返回隐藏资料。**其中dense使用常量协议向量，禁止用此报告计算语义效果提升、模型优劣或生产准确率。** 真实运行的[阻塞记录](../evals/examples/p2-01-blocked/report.md)明确没有执行质量样本；本地嵌入服务就绪后需重新对照并由真人检查相关性、遗漏和错误归因。没有替真人填写验收。

## 生命周期与回归

BM25只在请求内保存已授权词项计数，没有增加需异步删除的持久副本。删除、撤权、归档、扫描状态或发布代际变化后，新搜索和旧引用仍受P1-14门禁保护。分词和评分不重新写入制品，也不重复调用嵌入模型。

专项验证包括编号边界、中文术语与短语、无查询模型调用、跨租户/草稿/未检查排除、隐藏文档不影响员工评分、收据缺失显式失败、发布替换、并发撤权顺序、删除即时失效、CSRF和取消；另对既有全链路运行回归。浏览器验证通道切换、键盘检索、全角编号、来源复核、引号错误和390px布局。

本次验证：76项基础/单元测试、185项集成测试通过，合计261项；对共享检索、聊天、评测及词法通道另复跑50项门禁回归。桌面和390px浏览器无页面异常。21题协议观测与真实模型阻塞记录均已归档；没有新增迁移或依赖。
